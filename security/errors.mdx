## Forma de error

Los errores controlados usan `code` y `message`:

```json
{
  "code": "INTEGRATION_TOKEN_INVALID",
  "message": "Integration token is invalid or inactive"
}
```

## Códigos publicados

| HTTP | Código | Acción |
| --- | --- | --- |
| `400` | Validación de parámetros | Corrige UUID, fechas, booleanos o límites. |
| `401` | `INTEGRATION_TOKEN_INVALID` | Detén llamadas y revisa token, plan, licencia y activación. |
| `403` | `INTEGRATION_SCOPE_REQUIRED` | Solicita `employees:read`; no pruebes otro tenant. |
| `404` | `EMPLOYEE_NOT_FOUND` | El recurso no existe dentro del tenant autorizado. |
| `429` | `INTEGRATION_RATE_LIMIT_EXCEEDED` | Espera `retryAfterSeconds`. |
| `500` | `INTERNAL_ERROR` | Conserva la evidencia y aplica backoff antes de reintentar una lectura. |

Un `404` no confirma que el UUID exista en otra empresa. Un `401` deliberadamente no revela qué gate falló.

## Request IDs y auditoría

Cada solicitud autenticada recibe una identidad interna de request y genera auditoría por token, empresa, método, ruta, estado y duración. El secreto y los datos personales innecesarios no se copian al registro.
